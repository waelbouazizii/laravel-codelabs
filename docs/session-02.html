Branche, tag et dépôt distant

Une branche (ici main) est une étiquette mobile : à chaque commit, elle avance pour désigner le nouveau commit.

Un tag (par exemple lab-01) reste fixé sur un seul commit, pour toujours. C'est pourquoi chaque session se termine par un tag : il désigne l'état exact du projet à la fin de la session.

origin est le nom conventionnel du dépôt distant, ici votre dépôt GitHub.

Ce cours utilise HTTPS avec Git Credential Manager plutôt que des clés SSH, car une clé SSH laissée sur un poste partagé est plus difficile à nettoyer.

Votre identité dans l'historique

  • Chaque commit enregistre le user.name et le user.email configurés au moment du commit.
  • GitHub relie un commit à votre profil uniquement si cette adresse fait partie des adresses vérifiées de votre compte. Sinon, il affiche un nom gris, sans avatar.
  • L'historique est évalué : des commits sans lien avec votre compte ne peuvent pas vous être attribués.

S'authentifier sur un poste partagé

Au premier git push, Git Credential Manager ouvre le navigateur ; vous autorisez l'accès ; GCM range alors un jeton dans le Gestionnaire d'identification Windows (entrée git:https://github.com).

Ce jeton reste après votre départ : toute personne qui utilise ensuite la même session Windows pourrait pousser en votre nom. D'où le nettoyage obligatoire dans le Livrable, avec la déconnexion de github.com dans le navigateur.

  2. Saisissez exactement l'adresse affichée par la commande ci-dessus.

B. Tout le monde

  1. Connectez-vous sur https://github.com/login. Si GitHub demande un code de vérification de l'appareil, lisez-le dans votre messagerie sur votre téléphone.
  2. Ouvrez https://github.com/settings/emails.
  3. Contrôle 1 : votre adresse Git doit apparaître dans la liste, sans la mention « Unverified ». Si elle est absente, cliquez sur « Add email address », ajoutez-la, puis ouvrez le lien de vérification reçu par e-mail. Vos commits seront alors reliés automatiquement à votre profil : aucun commit n'a besoin de changer. Si l'adresse de git config n'est pas la vôtre (faute de frappe), elle sera corrigée à l'Étape 3.
  4. Contrôle 2 : regardez les deux cases « Keep my email addresses private » et « Block command line pushes that expose my email ». Si les DEUX sont cochées, décochez « Block command line pushes that expose my email ». Si vous ne le faites pas, votre push sera refusé avec l'erreur GH007.

Vos commits portent votre adresse réelle : elle est lisible dans l'historique de tout dépôt public. Beaucoup de développeurs utilisent une adresse dédiée à GitHub. Dans ce cours, l'adresse de git config doit être celle de votre compte.
