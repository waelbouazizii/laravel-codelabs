MVC, deuxième lecture : le côté Modèle 15 min

En session 04, les articles venaient d'un tableau PHP écrit dans le contrôleur : pour en ajouter un, il fallait modifier le code. Aujourd'hui, ils sont enregistrés dans une base de données, et la boîte en pointillés de la Figure 4.1 devient un vrai modèle.

Qu'est-ce qu'un ORM ?

Une base relationnelle range des lignes dans des tables ; PHP manipule des objets. Un ORM (Object-Relational Mapper) fait la traduction dans les deux sens. Celui de Laravel s'appelle Eloquent.

Eloquent ne remplace pas SQL : il l'écrit pour vous. Chaque objet sait aussi s'enregistrer lui-même avec $post->save() ; ce patron de conception s'appelle Active Record.

Aide-mémoire, à consulter pendant les étapes :

CRUD et contrôleur de ressource

CRUD désigne les quatre opérations de base sur des données enregistrées : Create, Read, Update, Delete. Un contrôleur de ressource les répartit sur sept méthodes.

Read (liste)GET/postsindexposts.indexSELECTS05
Create (formulaire)GET/posts/createcreateposts.createaucuneS05
Create (enregistrement)POST/postsstoreposts.storeINSERTS05
Read (un article)GET/posts/{post}showposts.showSELECTS05
Update (formulaire)GET/posts/{post}/editeditposts.editSELECTS06
Update (enregistrement)PUT/posts/{post}updateposts.updateUPDATES06
DeleteDELETE/posts/{post}destroyposts.destroyDELETES06

Create occupe deux routes : un GET pour afficher le formulaire, un POST pour enregistrer. Un GET ne modifie jamais les données.

Le cycle d'un formulaire

show(Post $post) : Laravel lit {post} dans l'URL, cherche l'article qui a cet id et le transmet à la méthode. S'il n'existe pas, la réponse est 404, sans aucun code de votre part.

Code complet

database/migrations/AAAA_MM_JJ_HHMMSS_create_posts_table.php :

<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    /**
     * Run the migrations.
     */
    public function up(): void
    {
        Schema::create('posts', function (Blueprint $table) {
            $table->id();
            $table->string('title');
            $table->string('slug')->unique();
            $table->text('body');
            $table->boolean('is_published')->default(false);
            $table->timestamp('published_at')->nullable();
            $table->timestamps();
        });
    }

    /**
     * Reverse the migrations.
     */
    public function down(): void
    {
        Schema::dropIfExists('posts');
    }
};

app/Models/Post.php :

<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Post extends Model
{
    protected $fillable = [
        'title',
        'slug',
        'body',
        'is_published',
        'published_at',
    ];

    protected function casts(): array
    {
        return [
            'is_published' => 'boolean',
            'published_at' => 'datetime',
        ];
    }
}

Laravel 13 accepte aussi des attributs PHP comme #[Fillable] à la place de la propriété. Ce cours utilise la propriété $fillable partout.

Résultat et vérification

  • migrate affiche la migration create_posts_table avec DONE.
  • db:table posts liste id, title, slug, body, is_published, published_at, created_at et updated_at.
  • Après le rollback, create_posts_table est Pending et les trois autres restent Ran.
  • Après le second migrate, tout est Ran.

Quiz éclair

Que défait php artisan migrate:rollback ?

Le rollback appelle down() pour les migrations du dernier lot, ici seulement create_posts_table.

À quoi sert le cast boolean sur is_published ?

SQLite stocke 1 ou 0 ; casts() convertit la valeur à la lecture et à l'écriture.

Score de la session : 0 / 0 (bonnes réponses au premier essai)

À retenir

Pourquoi ? up() construit, down() défait : une migration doit toujours pouvoir s'annuler. La migration donne sa forme à la table ; le modèle, lui, lit et écrit les lignes. Ajouter une colonne dans $fillable ne la crée pas dans la base.

Erreurs fréquentes : SQLSTATE[HY000]: General error: 1 table "posts" already exists : la table a été créée hors migration, ou le fichier a été modifié après coup ; lancez migrate:rollback puis migrate. Nothing to migrate. : le fichier de migration n'a pas été enregistré, ou il a déjà été exécuté.
