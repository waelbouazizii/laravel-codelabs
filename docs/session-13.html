Deuxième passage sur MVC : une Resource à la place de la vue 15 min

Une API sert des données, pas des pages. Un autre programme (une application mobile, un script, un autre site) lit le JSON et décide lui-même de l'affichage.

REST : chaque adresse désigne une ressource (/api/posts, /api/posts/3), le verbe HTTP dit l'action, et le code de statut dit le résultat.

Idée reçue à écarter : « l'API est une seconde application ». Elle lit la même base avec les mêmes modèles ; seule la porte d'entrée change.

Deux portes vers les mêmes modèles

Quiz éclair

Une application mobile veut afficher les articles de Mini-CMS. Pourquoi lui fournir /api/posts plutôt que la page /posts ?

Le JSON ne transporte que les données, dans une structure stable ; le HTML change à chaque retouche du design et l'application casserait. JSON n'est pas chiffré : c'est HTTPS qui chiffre.

Un client reçoit 422 en réponse à GET /api/posts?per_page=500. Que doit-il faire ?

Les codes 4xx désignent une erreur du client ; 422 signale des données invalides et la clé errors dit lesquelles. 401 demanderait une connexion, 5xx une panne du serveur.

Après install:api, où l'API lit-elle les articles ?

L'API est une autre porte vers les mêmes modèles. personal_access_tokens rangera les jetons de connexion de la session 15 ; elle ne contient aucun article.

use App\Http\Middleware\EnsureSiteIsWritable;
use App\Http\Middleware\EnsureUserIsAdmin;
use App\Models\Post;
use Illuminate\Database\Eloquent\ModelNotFoundException;
use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Exceptions;
use Illuminate\Foundation\Configuration\Middleware;
use Illuminate\Http\Request;
use Symfony\Component\HttpKernel\Exception\NotFoundHttpException;

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(
        web: __DIR__.'/../routes/web.php',
        api: __DIR__.'/../routes/api.php',
        commands: __DIR__.'/../routes/console.php',
        health: '/up',
    )
    ->withMiddleware(function (Middleware $middleware): void {
        $middleware->alias([
            'writable' => EnsureSiteIsWritable::class,
            'admin' => EnsureUserIsAdmin::class,
        ]);
    })
    ->withExceptions(function (Exceptions $exceptions): void {
        $exceptions->shouldRenderJsonWhen(
            fn (Request $request) => $request->is('api/*') || $request->expectsJson(),
        );

        $exceptions->render(function (NotFoundHttpException $e, Request $request) {
            if ($request->is('api/*') || $request->expectsJson()) {
                return null;
            }

            $previous = $e->getPrevious();

            if ($previous instanceof ModelNotFoundException && $previous->getModel() === Post::class) {
                return response()->view('errors.article-introuvable', [], 404);
            }

            return null;
        });
    })->create();

Quiz éclair

Dans la réponse brute de /api/posts, quel problème la clé user pose-t-elle ?

#[Hidden] ne masque que password et remember_token (session 11). email, email_verified_at et role partent chez n'importe quel client : une Resource choisit les champs envoyés (Étape 3).

Les noms sont communs à tout le projet. En développement, route() garde la route du site, chargée en dernier, et le doublon passe inaperçu ; route:cache, lancé lors des mises en production, refuse deux routes du même nom.

app/Http/Resources/PostResource.php (contenu complet) :

<?php

namespace App\Http\Resources;

use Illuminate\Http\Request;
use Illuminate\Http\Resources\Json\JsonResource;

class PostResource extends JsonResource
{
    /**
     * Transform the resource into an array.
     *
     * @return array<string, mixed>
     */
    public function toArray(Request $request): array
    {
        return [
            'id' => $this->id,
            'title' => $this->title,
            'slug' => $this->slug,
            'excerpt' => $this->excerpt,
            'published_at' => $this->published_at?->toIso8601String(),
            'url' => route('posts.show', $this->resource),
        ];
    }
}
  • $this->title lit la colonne du modèle enveloppé ; $this->resource est le modèle lui-même.
  • ?-> protège une date null.
  • url mène à la page du site : route('posts.show') reste la route du site grâce au préfixe api. de l'Étape 2.
  • body revient dans le défi.

app/Http/Controllers/Api/PostController.php (contenu complet) :

<?php

namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use App\Http\Requests\Api\IndexPostRequest;
use App\Http\Resources\PostResource;
use App\Models\Post;
use Illuminate\Http\Resources\Json\AnonymousResourceCollection;
use Illuminate\Support\Facades\Gate;

class PostController extends Controller
{
    /**
     * Display a listing of the resource.
     */
    public function index(IndexPostRequest $request): AnonymousResourceCollection
    {
        $perPage = (int) ($request->validated('per_page') ?? 5);

        $posts = Post::published()
            ->with('user', 'category')
            ->latest('id')
            ->paginate($perPage)
            ->withQueryString();

        return PostResource::collection($posts);
    }

    /**
     * Display the specified resource.
     */
    public function show(Post $post): PostResource
    {
        Gate::authorize('view', $post);

        return new PostResource($post->load('user', 'category'));
    }
}
  • ?? 5 couvre une adresse sans per_page et ?per_page= vide (Laravel transforme la chaîne vide en null).
  • withQueryString() garde per_page dans les liens de links.
  • Gate::authorize('view') réutilise PostPolicy::view de la session 12 : dans l'API, l'utilisateur est toujours un visiteur.
