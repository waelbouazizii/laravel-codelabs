Voir des éléments de réponse

1. PostPolicy : une seule règle décide qui peut modifier ou supprimer un article, pour le site comme pour l'API. Si la règle change, les deux portes changent ensemble, et l'API ne peut pas devenir un raccourci qui contourne les droits du site.

2. preventLazyLoading : une relation lue dans une boucle sans chargement anticipé produit une requête par élément (N+1). En développement, l'option transforme ce problème silencieux en erreur visible ; elle reste désactivée en production pour ne pas casser le site.

3. Jetons : le groupe api n'a ni session ni cookie. Un client qui n'est pas un navigateur (application, script, Postman) présente donc un jeton à chaque requête ; ce jeton se révoque seul, sans toucher aux autres appareils.

Voir des éléments de réponse
